Bullet Time from one phone shot

Freeze any moment of your take and fly the camera around it, the way a ring of 100 cameras would. Then the camera lands back on your real frame and the take carries on, with its real sound.

Get it on GitHub Run it in 3 commands

One take in, bullet time out

The app finds the peak of the action, freezes it, makes 8 camera views of that exact frame with Qwen-Image-Edit 2511, and lets LTX-2.3 fly the camera through them while time stands still. The whoosh is generated in the same pass.

The real frame, then the 8 generated views (front quarters, sides, back, high angle).

How it works

real take ..... | slow-mo ramp | camera orbits the frozen moment | rewinds home | real take resumes ..... real audio .... | pitched down | generated whoosh (LTX audio) | reversed | real audio ............

Pick the moment

OpenCV scores every frame by motion x sharpness, so the freeze lands on the peak without blur. Scrub to override.

free, CPU

8 views

Qwen-Image-Edit 2511 with the Multiple-Angles LoRA, prompted in its trained format and matched to your framing. Sideways or wrong views are rejected.

1 job · ~$0.045

The orbit

LTX-2.3 22B: your real frame in the latent, each view an LTXVAddGuide keyframe, two stages up to 704x1280, audio included.

1 job · ~$0.055

Splice

ffmpeg ramps into the freeze, plays the orbit, rewinds home and resumes on the very frame it froze on. Both cuts land on the same image.

Run it

Python 3.10+ and ffmpeg. No local GPU: generation runs on Comfy Cloud with your own key, about $0.10 per bullet time.

git clone https://github.com/apsolut/bullet-time-comfyui && cd bullet-time-comfyui
python -m venv .venv && .venv\Scripts\activate     # macOS/Linux: . .venv/bin/activate
pip install -e .
bullettime serve                                  # http://127.0.0.1:8790

Prefer ComfyUI itself? The exact API graphs are in workflows/, and the web app downloads the graphs used for each result.
